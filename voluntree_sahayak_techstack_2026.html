Field data capture

Audio → Cloud Speech-to-Text v2 (Chirp) streaming/batch → transcript. Image (clear form) → Document AI Form Parser → key-value JSON. Image (freeform/handwritten) → Gemini 2.5 Pro Vision → structured extraction. Route decision made by content-type header.

Transcript or OCR text → Gemini 2.5 Flash with schema-constrained JSON prompt → {location, need_type, severity, beneficiary_count, language, urgency_notes}. LangChain LCEL chain (optional): input routing → extraction chain → validation chain → retry on schema failure. Confirmation message sent back via WhatsApp.

Urgency scoring + embedding
Rule engine: need_type × severity × repetition_count × beneficiary_count → 0–100 score. Parallel: Vertex AI text-embedding-004 embeds need description. Embeddings stored in Firestore vector field (or Vertex AI Vector Search / Pinecone for Phase 2 scale). Burst anomaly: Pub/Sub message count spike → alert.

6
Volunteer matching + AI explanation
Cloud Run matching service: filter by skill keyword + Haversine radius + availability window → cosine similarity rank on embeddings → top 3. Gemini Flash generates 1-sentence human-readable reason per match (e.g. "Rajan: plumber, 2.1 km, available today, 89% completion rate"). Coordinator sees suggested list — never auto-assigned.
Cloud Run (Python FastAPI)Gemini 2.5 FlashVertex AI Vector Search
7
Dashboard + coordinator approval
Flutter Web coordinator dashboard: real-time Firestore listener updates live map (urgency-colored pulsing pins), urgency queue, AI summary card with ✦ label and editable fields. Coordinator approves assignment with one tap. AI summary shown with confidence score; if <70% → "⚠ verify manually" badge (per VolunTree spec).

Volunteer dispatch + feedback loop
On coordinator approval → FCM push to volunteer app (free, primary). WhatsApp template message as fallback for volunteers without app. Volunteer accepts/declines/completes → status written to Firestore → dashboard updates live. Completion data flows to BigQuery (Phase 2) for model retraining.

Frontend Flutter 3.x · Android + Web · single codebase
Flutter 3.x (Dart)
PrimaryFree
Single codebase for Android field app (1.5GB RAM / Android 8+ target per VolunTree spec) and Flutter Web coordinator dashboard. Riverpod 2.4 state management, offline Hive boxes, workmanager background sync — all specified in VolunTree's package list. No alternative delivers offline-first + Web + Android in one codebase this efficiently.
Free · Google-maintained · GCP CI/CD native
Noto Sans + Poppins
Typography
Noto Sans: full Devanagari, Tamil, Telugu, Kannada, Punjabi rendering — mandatory for VolunTree's 6 Indian languages. Poppins for display headers. Both via Google Fonts CDN, pre-load in pubspec.yaml to avoid FOUT on 2G.
flutter_map + OpenStreetMap
Maps (mobile)
flutter_map with cached OSM tiles for field worker Android app — works fully offline, zero cost. Google Maps SDK only for coordinator Web dashboard where heatmap layers and Places API needed. Matches VolunTree spec exactly.

Cloud Functions Gen 2 (Node.js 20 / Python 3.12)
Webhooks + triggers2M req/month free
Webhook receiver for Twilio/Meta WhatsApp inbound. Firestore onCreate trigger fires extraction pipeline. Gen 2 (Cloud Run-backed) gives 60-min timeout — critical for large audio files on slow 2G connections. Gen 1's 9-min limit would cause silent failures on rural uploads.
2M invocations/month free · Gen 2 scales to 1000 instances
Cloud Pub/Sub
Event bus10GB/month free
Decouples WhatsApp webhook from AI processing. Webhook publishes to "raw-reports" → subscriber function calls Gemini. Essential for disaster-event burst tolerance — 500 simultaneous flood reports won't crash the extraction pipeline. Dead-letter topic catches and retries failures.
10GB messages/month free · at-least-once delivery guaranteed
Cloud Run (Python FastAPI)
Matching engine2M req/month free
Volunteer matching is CPU-bound with Vertex embedding queries — needs more control and memory than Cloud Functions. FastAPI container deployed to Cloud Run. Scales to zero between calls. Called by Cloud Function after report is structured and scored.
180,000 vCPU-seconds/month free · cold start ~400ms acceptable for non-realtime matching
Twilio WhatsApp API
Intake (sandbox)
Inbound only — field workers send photos/voice. Sandbox free for demo. Production: switch to Meta Cloud API (free up to 1K conversations/month) to eliminate per-message cost.
Meta WhatsApp Cloud API
Intake (production alt)
Free tier: 1,000 service conversations/month. No Twilio markup. Same webhook format — just a URL swap. Preferred for post-demo production deployment to eliminate per-message cost on inbound.
LangChain LCEL (optional)
Chain orchestrationOpen-source
Use for multi-step Gemini workflows: input router → STT transcript cleaner → extraction chain → JSON schema validator → retry on failure → explanation generator. Adds retry logic, streaming, and structured output parsing cleanly. Optional — three direct Gemini API calls work fine for MVP without it. Use if chain complexity grows beyond 3 steps.
Open-source · Apache 2.0 · no additional cost · add langchain-google-vertexai package
Auth No email. No password. Rural-first.
Firebase Auth — Phone OTP
Primary authFree
VolunTree spec explicitly rejects email/password. Coordinator pre-assigns phone numbers; field workers get OTP on their existing SIM — zero typing of usernames. 4-digit PIN stored locally in Hive with bcrypt hash. Biometric (local_auth) unlocks without re-auth. Session preserved 1 hour if backgrounded (per VolunTree spec).
10K phone verifications/month free · India SMS OTP delivery ~98% reliable
Firebase App Check
API abuse prevention
Attests requests come from genuine VolunTree APK. Prevents unauthorized callers from burning Gemini API quota. Must be enabled before any public launch — a single script can exhaust free tier in minutes without it.
Free · mandatory pre-launch
Firestore Security Rules
Data authorization
Role-based: field_worker (write own reports), volunteer (read assigned tasks, write completion), coordinator (read all, write assignments), admin (full). NGO tenant isolation via tenant_id field — no cross-NGO data leakage.
Database Offline-first · real-time · analytics-ready
Firestore (Native mode)
Operational DBFree tier generous
Offline persistence SDK handles VolunTree's offline-first requirement automatically — queues writes locally, syncs on reconnect, zero extra code. Real-time listeners power coordinator dashboard live map. Supports vector field for embedding storage (Phase 1 matching). Collections: /reports · /volunteers · /assignments · /ngos · /urgency_scores.

Hive (Flutter on-device)
Local storeFree
VolunTree spec explicitly defines Hive boxes: pendingReports (ReportModel: id, issueType, imagePath, audioPath, lat/lng, createdAt, SyncStatus, retryCount) + userPrefs + cachedCases. Survives app kill. workmanager uploads on background reconnect.
Cloud Storage (GCS)
Media store
Survey photos (auto-compressed 800px / ~200KB per VolunTree spec), voice .m4a files, PDF uploads. Signed URIs passed to Gemini Vision — never send raw bytes from mobile. Lifecycle rules auto-archive after 90 days.
5GB/month free · lifecycle archival to Coldline reduces cost 80%
Vertex AI Vector Search
Embeddings (Phase 1)
Stores text-embedding-004 vectors for volunteer profiles and need descriptions. Sub-100ms ANN search for matching. GCP-native alternative to Pinecone — no external dependency, better latency, integrates directly with Vertex AI SDK.
~$0.10/hr for small index · covers demo + early users well within budget
Pinecone (Phase 2 alt)
Vector DB (alt)
Free tier: 1 index, 100K vectors, 5 projects. Useful if team is more comfortable with Pinecone's SDK than Vertex AI. Slight vendor lock-in and external dependency vs native Vertex. Prefer Vertex Matching Engine for GCP-first architecture.
Free tier (1 pod, 100K vectors) · paid if scale demands it
BigQuery (Phase 2)

Gemini 2.5 Flash
PRIMARY LLM
Core extraction call: OCR text / STT transcript → schema-constrained JSON. Also generates 1-sentence volunteer match explanation and auto donor report. 3 calls per report lifecycle. Flash not Pro — 5× cheaper, 3× faster, sufficient for single-report extraction.
Free tier via AI Studio
Gemini 2.5 Pro Vision
VISION FALLBACK
Complex handwriting, multi-page forms, poor-lighting photos where Flash confidence <70%. Routes via Remote Config threshold. Pro's superior vision reasoning handles marginalia, mixed Hindi-English tables, blurry field photos better than any OCR-only solution.
Paid — use sparingly
Gemini 2.5 Flash (translation)
MULTILINGUAL
Translates AI summary card and volunteer task brief into coordinator's preferred language (6 Indian languages per VolunTree spec). Replaces Google Translate API — Gemini handles code-switching ("yahan paani nahi hai, need help fast") more naturally than pure translation APIs.
Included in Flash quota
Document AI Form Parser
STRUCTURED FORMS
Handles NGOs using standardized printed surveys with fixed field positions, checkboxes, and printed labels. Form Parser extracts key-value pairs from semi-structured forms more reliably and cheaply than a general LLM. Route: known template form → Document AI; freeform photo → Gemini Vision.
1K pages/month free
Cloud Speech-to-Text v2 (Chirp)
VOICE PIPELINE
Server-side: batch recognition for WhatsApp voice notes + streaming for live waveform feedback on Flutter capture screen. Chirp handles Hindi/Marathi/Tamil/Telugu code-switching and background noise (field conditions) far better than on-device speech_to_text package. On-device STT (Flutter pkg) still used for real-time waveform animation only.
60 min/month free
Vertex AI text-embedding-004
EMBEDDINGS
768-dimensional multilingual embeddings for volunteer skill profiles and need descriptions. Powers semantic matching (e.g. "nursing" matches "medical care" / "swasthya seva"). Stored in Vertex AI Vector Search. Weekly re-embedding batch job updates volunteer profiles as skills are updated.
Free in Vertex AI quota
Gemma 3 (self-hosted)
PHASE 2 OPTION
Open-weight alternative for extraction pipeline if Gemini API costs grow at scale. Deploy Gemma 3 12B on Cloud Run GPU or Vertex AI endpoints. Can be fine-tuned on NGO-specific vocabulary (district names, scheme names, local issue terminology) for better accuracy than zero-shot Gemini Flash on niche inputs.
Vertex AI cost for serving
Llama 3.1 (via Vertex Model Garden)
PHASE 2 OPTION
Available in Vertex AI Model Garden. Viable fallback if open-weight model needed for on-premise NGO deployment (data sovereignty requirement). Not needed for demo or Phase 1. Only consider if an NGO partner requires data to stay on their own infra.
Vertex serving cost
Vertex AI AutoML / XGBoost
PHASE 2 ML
Train urgency classifier on manually-confirmed coordinator labels once 500+ cases exist. XGBoost on 8 tabular features (need_type, severity, beneficiary_count, repetition, location_density, time_since_last_report, weather_flag, population_vulnerability). Replaces rule engine with learned model. Vertex AI managed training + online endpoint.
Phase 2 — needs labelled data

Apps Script → Cloud Functions migration path
NGO onboarding bridge
NGOs already managing data in Google Sheets can use a lightweight Apps Script that fires on sheet edit → POST to Cloud Function endpoint → report enters Sahayak pipeline. Zero new tool adoption for those NGOs. Migration path: Apps Script (immediate adoption) → native Flutter app upload (when trust established). One doFetch() call in Apps Script is the entire integration.
Free · Apps Script quota: 6min execution, 20K URL fetch calls/day — sufficient for NGO scale

Key pipelines summary
Voice intake pipeline
WhatsApp voice note → Twilio webhook → Cloud Function → Pub/Sub "raw-reports" → Chirp STT (batch) → Gemini 2.5 Flash extraction → JSON validation → Firestore write → WhatsApp confirmation reply
Image intake pipeline
Photo → Cloud Storage upload → GCS URI → [if known form template] Document AI Form Parser → [else] Gemini 2.5 Flash Vision → [if confidence <70%] Gemini 2.5 Pro Vision → structured JSON → Firestore
Volunteer matching pipeline
New Firestore report → Cloud Function trigger → urgency rule engine (score 0–100) → Vertex text-embedding-004 (need description) → Cloud Run: filter (radius + skill + availability) + cosine similarity rank → top 3 volunteers → Gemini Flash explanation cards → Firestore suggestions field
Coordinator approval → dispatch pipeline
Coordinator taps "Assign" (Flutter Web) → Firestore write (assignment status) → Cloud Function trigger → FCM push to volunteer app (primary) → WhatsApp template fallback (if no app) → Volunteer accepts → Firestore status update → Dashboard live update via Firestore listener
Apps Script → Sahayak bridge (NGO onboarding)
NGO Google Sheet row added → Apps Script onEdit trigger → UrlFetchApp.fetch(cloudFunctionURL, payload) → Cloud Function receives structured row → skips STT/OCR (already structured) → urgency scoring + matching pipeline as normal
Offline sync pipeline (Flutter field app)
Capture (offline) → Hive local write (ReportModel + imagePath + audioPath) → connectivityProvider detects 2G+ → workmanager background task → Cloud Storage upload (photo/audio) → Firestore write (metadata) → Hive status = synced → UI queue card: ✓ checkmark animation
GCP-native vs Pinecone decision: Use Firestore vector field (free, built-in) for MVP with <10K volunteer profiles. Move to Vertex AI Vector Search when volunteer count grows — it's GCP-native, no external dependency, sub-100ms ANN search. Pinecone is viable if the team has prior experience with it, but introduces vendor lock-in and an additional paid dependency with no GCP-native advantage.
LangChain decision: 3 direct Gemini API calls (extract → explain → translate) work fine for MVP without LangChain. Add LangChain LCEL if: chain has 4+ steps, you need structured retry logic on schema failures, or you want streaming output to the Flutter UI. The langchain-google-vertexai integration is stable and adds minimal overhead.
